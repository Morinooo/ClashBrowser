# ClashBrowser v1.16.4

- versionName: `1.16.4`
- versionCode: `28`
- minSdk 26 / targetSdk 34 / arm64-v8a

Root-cause fix for the crash reported on Android 16 / WebView 150: typing a URL
and pressing Enter killed the app the moment a page was opened.

## Fixed

### `allowedOriginRules http://* is invalid`

The app injects three document-start scripts (EME fallback, touch-context
capture, WebRTC leak block). They were registered like this:

```kotlin
WebViewCompat.addDocumentStartJavaScript(wv, script, setOf("http://*", "https://*"))
```

`allowedOriginRules` only accepts the WebView origin format — `*`,
`https://example.com`, or `https://*.example.com`. `http://*` and `https://*`
are invalid. WebView builds up to ~14x silently accepted them, but
**WebView 150.0.7871.46 (Chromium) validates strictly** and throws

```
java.lang.IllegalArgumentException: allowedOriginRules http://* is invalid
```

while the WebView is constructed — i.e. exactly on the first page load. Because
the rules were introduced in v1.16.1, **every build from v1.16.1 onwards crashed
the same way**, which is why reinstalling an "older" APK did not help. v1.16.3's
crash containment turned the silent exit into a copyable error report, which is
how this was finally pinned down.

Fix:

- use the valid all-origins rule `*`;
- the three scripts now check `location.protocol` themselves, so injection still
  only takes effect on `http:`/`https:` documents (the v1.16.1 hardening intent
  is preserved, without relying on an illegal wildcard);
- wrap each `addDocumentStartJavaScript` in `runCatching`, so any future
  WebView-side validation change degrades an optional enhancement instead of
  breaking the browser;
- add `WebViewScriptsTest` as a regression guard (format check + forbids
  `http://*` / `https://*` from coming back + asserts the protocol guard).

中文说明：根因是 v1.16.1 把预注入脚本的来源规则写成了非法的 `http://*` / `https://*`；
WebView 150 开始严格校验，创建网页视图时直接抛异常导致闪退——所以 v1.16.1 之后的版本全都崩，
重装"旧版"也无效。现在改用合法的全来源 `*`，并让脚本自己按 http/https 协议限制作用范围，
同时每个注入单独容错，并加了回归单测，防止再写回去。

## Notes

- No behaviour change for devices whose WebView accepted the old rules; the only
  difference is that the injected scripts skip non-http(s) documents by
  themselves instead of relying on the origin filter.
- Unit tests: 34 cases (`WebViewScriptsTest` adds 3).

中文说明：对原本能用的设备行为不变；唯一区别是脚本不再依赖来源过滤，而是自行判断协议。
单测共 34 例。
