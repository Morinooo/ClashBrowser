# ClashBrowser v1.16.1

- versionName: `1.16.1`
- versionCode: `25`
- minSdk 26 / targetSdk 34 / arm64-v8a

## Security

Five externally reported hardening items, fixed together (patch release per
semver: security fixes, no new features).

### 1. Local port & API isolation
- Generated mihomo config now pins `bind-address: 127.0.0.1` explicitly in
  addition to `allow-lan: false` and `external-controller: 127.0.0.1:9090`;
  no listener is reachable from the LAN.
- The REST API `secret` is no longer an empty string: a random 32-hex secret is
  generated on every app start, written into the runtime config, and sent as
  `Authorization: Bearer …` on every Clash REST call (version / proxies /
  configs / reload / mode).
- Stale orphan kernel cleanup from previous sessions is retained.

### 2. IP / trace leak prevention
- WebRTC: a document-start script disables `RTCPeerConnection` (and webkit/moz
  aliases) so ICE candidates cannot expose the real IP behind the proxy.
  Forced in incognito tabs; normal tabs get a new Toolbox → More →
  "WebRTC 防泄露" switch (default off, applies by recreating WebViews).
- Incognito exit already clears per-host Cookies and cache and never writes
  session snapshots; re-verified unchanged.

### 3. Subscription & log redaction, encrypted at-rest storage, import caps
- `maskUrl` / `maskText` hide query and fragment (token parameters) of any
  http(s) URL in kernel/app logs and subscription error messages; over-long
  path segments are no longer used as profile names.
- At-rest encryption via Android Keystore AES/GCM (SecretStore): subscription
  URL list, active-subscription pointer, per-profile YAML archives and a
  config master copy (`config.enc`) are stored encrypted. Plaintext exists
  only in the app-private runtime dir while the kernel needs it; process-exit
  paths (`onTaskRemoved` / service `onDestroy`) wipe runtime plaintext.
  Legacy plaintext values are migrated to encrypted on first read.
- Import fallbacks: bookmark HTML ≤ 5 MB and ≤ 20 000 tokens; subscription
  body and YAML ≤ 2 MB (SnakeYAML codePointLimit), oversized input rejected
  with a clear error instead of OOM.

### 4. WebView & navigation boundaries
- Document-start JS injection (EME fallback, context capture, WebRTC block)
  is scoped to `http://*` / `https://*` instead of `*` (no file:// etc.).
- Non-http(s) navigations (intent:// and other schemes) stay blocked and now
  show a toast naming the blocked scheme.
- FileProvider sharing re-audited: single-URI `FLAG_GRANT_READ_URI_PERMISSION`
  only, paths limited to cache/share and external Download subdirs.

### 5. Kernel & release supply chain
- mihomo pinned to `v1.19.34`; the build downloads that exact tag and verifies
  the gz SHA-256 (`48a71fc6…359b5`), failing the build on mismatch.
- Geo databases (country-lite.mmdb / geosite.dat) are vendored into repo
  assets at pinned hashes and verified at build time (upstream meta-rules-dat
  uses a rolling `latest` tag, so vendoring keeps CI reproducible).
- Release build: explicit `isDebuggable = false`, R8 minification enabled with
  keep rules for `@JavascriptInterface` members and SnakeYAML reflection;
  signing stays isolated in CI secrets (debug and release never overwrite
  each other).
