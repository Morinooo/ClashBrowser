# ClashBrowser v1.16.2

- versionName: `1.16.2`
- versionCode: `26`
- minSdk 26 / targetSdk 34 / arm64-v8a

Two user-reported behaviour fixes. No new features, no permission changes.

## Fixed

### 1. Deleting a profile now really removes its policy groups and nodes

Deleting a subscription profile used to only drop the profile card: the policy
groups / node list fetched from that profile stayed in the proxy panel, and if
the deleted profile was the active one, its configuration kept running.

- Delete now asks for confirmation and states whether the profile is the one
  currently in effect.
- Deleting the active profile applies the next remaining profile automatically
  (hot reload through `PUT /configs?force=true`).
- Deleting the last profile resets the runtime configuration to the default
  direct config (`proxies: []`, `MATCH,DIRECT`), so the old groups disappear.
- When the core is not running, the panel clears its node/group caches instead
  of showing a stale list next to "内核未运行".
- The delete path never starts the core by itself when the proxy switch is off;
  it only updates the on-disk configuration.

中文说明：删除订阅配置时会先二次确认；删的是当前生效配置会自动切到剩下的配置，
删掉最后一个则恢复默认直连配置；内核没在运行时不再显示上一次订阅的"僵尸节点"。

### 2. No more local-port competition with other proxy apps

The embedded mihomo core used the Clash-default local ports `7890` (mixed) /
`9090` (REST) / `1053` (DNS). Because the core keeps running while the app is in
the background (it is only killed when the task is swiped away), starting
another Clash-style proxy app afterwards failed to bind those ports and appeared
broken — the "port competition" reported by users.

- Dedicated ports: `mixed-port: 17890`, `external-controller
  127.0.0.1:19090`, DNS `127.0.0.1:11053`.
- If a dedicated port is already occupied by something else, the app scans the
  next ports (10 candidates) and uses the first free one; the config, the
  WebView `ProxyController` override, image/download OkHttp proxy and the panel
  status line all use the port actually chosen for this session.
- A subscription-provided `dns.listen` is rewritten to the dedicated DNS port,
  so importing a config cannot reintroduce the `1053` clash.
- The loopback self-loop check for imported nodes now compares against the
  chosen mixed port instead of a hardcoded `7890`.

中文说明：内核改用专用端口（17890/19090/11053），被占用时自动顺延取空闲端口；
应用挂后台时不再占用别的 Clash 客户端的默认端口，两个软件可以同时运行。

## Changed

## Notes

- Unit tests: `ProxyConfigTest` now asserts the dedicated ports and the
  `dns.listen` rewrite (suite: 31 cases).
- Existing installs keep their saved profiles: `config.yaml` is re-patched with
  the new ports on next launch, so no manual migration is needed.
- Remaining backlog unchanged: user scripts, gesture navigation, site
  permission manager beyond geolocation, additional ABIs.
