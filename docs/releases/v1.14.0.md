# ClashBrowser v1.14.0

> 版本梳理：本 release 由旧 tag v1.7.0 重命名而来；APK 由原 commit 代码快照重建，
> versionName 已同步为 1.14.0（versionCode 21 不变）。新旧编号对照见 CHANGELOG。

- versionName: `1.14.0`
- versionCode: `21`
- minSdk 26 / targetSdk 34 / arm64-v8a

## Added

### Download manager
- `WebView.setDownloadListener` captures non-image downloads; a toast announces
  the file name and the task appears in Toolbox → 下载管理.
- Streaming download (64 KB chunks) with throttled progress updates; progress
  bar + transferred/total size in the task list.
- Storage: API 29+ → MediaStore `Download/ClashBrowser` (visible in system file
  manager, no permission); API 26–28 → app-private external `Download/` dir
  (no permission). Manifest still declares only INTERNET and
  ACCESS_NETWORK_STATE.
- Requests reuse the proxy-aware OkHttp client (follows the in-app proxy when
  enabled) and attach the WebView session cookie + listener user-agent.
- Task metadata persists in `download_prefs`; tasks interrupted by process
  death are restored as failed with reason "上次退出时中断" and can be retried.
- Failed tasks: retry (fresh download). Completed tasks: open via ACTION_VIEW
  with FileProvider (API < 29) or MediaStore URI (API 29+); a toast explains
  when no app can handle the file. Delete asks for confirmation and removes
  both record and file.
- FileProvider paths extended with `external-files-path Download/`.

### File upload
- `WebChromeClient.onShowFileChooser` implemented: launches the system file
  picker via `FileChooserParams.createIntent()` (multi-select honored),
  returns URIs through `FileChooserParams.parseResult`; cancel/failure paths
  always release the callback so the page never hangs.

## Notes
- Image long-press save/share keeps using the existing MediaActions path;
  the download manager handles everything else (archives, documents, APKs…).
- Remaining backlog (in order): in-page find, selectable search engine, true
  desktop viewport, incognito isolation, reader mode, media sniffer,
  subscription-userinfo parsing hardening.
