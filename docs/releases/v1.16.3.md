# ClashBrowser v1.16.3

- versionName: `1.16.3`
- versionCode: `27`
- minSdk 26 / targetSdk 34 / arm64-v8a

Emergency crash fix. No new features beyond crash containment and diagnostics.

## Fixed

### Instant crash when opening the first page (search box → Enter)

On some devices (reported on Android 16 / Snapdragon 8 Elite Gen 5) the app
closed instantly when the first page was opened: the home screen is pure
Compose and worked, but the moment a WebView was created and asked to load a
URL the process died with no message. Older APKs behaved identically, which
matches this being an unguarded WebView failure rather than a regression: the
affected code paths are byte-identical between v1.16.1 and v1.16.2.

The app now treats the WebView as a component that can fail:

- It verifies that a system WebView provider exists and that the WebView build
  supports proxy overrides (`WebViewFeature.PROXY_OVERRIDE`) before using them.
- WebView creation and `loadUrl` are wrapped; on failure the app shows an error
  page with: cause, device/WebView version, "retry", "copy details",
  "open WebView settings" (to update or clear Android System WebView / Chrome
  data) and "back to home" — no more silent crash.

中文说明：这次闪退不是 v1.16.2 引入的（崩溃链路的代码与 v1.16.1 完全一致，与你重装旧版仍复现相符）。
根因是应用此前对"系统 WebView 创建/加载失败"没有任何兜底，底层一崩应用就闪退。
现在会把网页组件当作"可能失败的部件"处理：先检测可用性与代理能力，失败时显示可操作的错误页而不是退出。

## Added

### Local crash diagnostics (offline, no telemetry)

- Uncaught Java exceptions are written to app-private storage and shown on the
  next launch in a dialog with a copy button.
- A "WebView session in progress" marker records the case that a native crash
  leaves no Java trace: if the process disappears while a web view is being
  created/loaded, the next launch reports it and includes Android version,
  device model and WebView package/version.
- Nothing is uploaded; records stay on the device and can be deleted from the
  dialog.

中文说明：崩溃信息只写在手机本地（不上传），下次打开会弹窗显示并可一键复制，方便反馈；关闭弹窗即删除记录。

### Safe mode

If the last run died while opening a web view, the next launch enters safe mode:
the embedded core and the WebView proxy override are skipped, so pages load
(directly) — the proxy override is the most likely crash trigger on affected
WebView builds. A top banner explains it and offers "retry proxy"; an explicit
enable/restart in the proxy panel also retries and, on success, leaves safe mode.

中文说明：安全模式 = 上次死在打开网页的链路，本次先不启用代理、网页直连，保证能用；
点页顶"重试代理"或在代理面板手动开启代理即可恢复。若恢复后仍崩溃，日志会再次记录下来。

## Notes

- Crash dialogs from the system are sometimes suppressed by OEM ROMs; the
  in-app report is the reliable way to capture the stack for this issue.
- Remaining backlog unchanged.

中文说明：若你已能复现闪退，请升级后再试一次；如果仍然闪退，下次打开会弹出"上次运行诊断信息"，
点"复制详情"把内容发给我即可精确定位（若连诊断弹窗都来不及出现，说明是原生层被杀，
安全模式仍会让应用可用，并会在下次启动报告）。
